# 1. Назначение документа

Документ описывает структуру проекта HighSpeedVPN, организацию исходного кода и основные принципы разработки.

Проект разрабатывается по модульной архитектуре. На этапе MVP для управления VPN используется готовый сервис **amnezia-api**. Архитектура проекта должна позволять в дальнейшем заменить его на собственный Backend без существенных изменений остальной системы.

# 4. Назначение директорий

## bot/

Содержит Telegram-бота.

Включает:

* команды;
* обработчики сообщений;
* обработчики callback-запросов;
* меню;
* FSM;
* middleware.

---

## api/

REST API Backend.

Содержит:

* маршруты;
* контроллеры;
* DTO;
* схемы валидации;
* обработчики ошибок.

---

## services/

Содержит бизнес-логику проекта.

Основные сервисы:

* UserService;
* SubscriptionService;
* PaymentService;
* TariffService;
* NotificationService;
* VPNService.

---

## VPNService

VPNService является единственной точкой взаимодействия с VPN-инфраструктурой.

На этапе MVP сервис обращается к **amnezia-api**.

Все остальные компоненты системы работают только с VPNService и не взаимодействуют с amnezia-api напрямую.

В обязанности VPNService входит:

* создание VPN-клиента;
* удаление VPN-клиента;
* получение конфигурации;
* продление доступа;
* блокировка клиента;
* выбор VPN-сервера;
* получение информации о сервере.

---

## repositories/

Слой доступа к данным.

Каждый репозиторий отвечает только за операции с PostgreSQL.

Бизнес-логика в репозиториях отсутствует.

---

## middleware/

Общие обработчики.

Например:

* авторизация;
* логирование;
* обработка ошибок;
* проверка прав доступа.

---

## database/

Подключение к PostgreSQL.

Содержит:

* подключение;
* миграции;
* сиды;
* конфигурацию.

---

## config/

Настройки проекта.

Включает:

* параметры Telegram;
* параметры PostgreSQL;
* настройки amnezia-api;
* настройки JWT;
* переменные окружения.

---

## logger/

Единая система логирования проекта.

---

## utils/

Вспомогательные функции общего назначения.

---

## types/

Общие типы TypeScript.

# 7. Принципы разработки

При разработке необходимо соблюдать следующие правила:

* один модуль — одна ответственность;
* разделение бизнес-логики и хранения данных;
* отсутствие прямых обращений к базе данных из Telegram-бота;
* отсутствие прямых обращений к amnezia-api из Telegram-бота;
* взаимодействие с VPN только через VPNService;
* использование конфигурации через переменные окружения;
* единый стиль именования файлов и компонентов.

---

# 8. Подготовка к развитию проекта

Несмотря на использование готового amnezia-api, архитектура должна позволять заменить его на собственный сервис управления VPN.

Для этого:

* вся работа с VPN сосредоточена в VPNService;
* остальные части системы не знают о внутреннем устройстве amnezia-api;
* интерфейс VPNService должен оставаться стабильным при смене реализации.

# 10. Итог

Структура проекта HighSpeedVPN ориентирована на модульность и возможность постепенного развития. На первом этапе используется готовый **amnezia-api**, что позволяет быстро реализовать MVP и проверить работоспособность всех основных сценариев. При необходимости архитектура позволит заменить его на собственный сервис управления VPN без изменения Telegram-бота, бизнес-логики и базы данных.
