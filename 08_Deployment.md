# HighSpeedVPN — Deployment

**Версия документа:** 1.0
**Дата создания:** 05.08.2026
**Статус:** В разработке

---

# 1. Назначение документа

Документ описывает процесс развертывания HighSpeedVPN, состав инфраструктуры, используемые сервисы и правила эксплуатации.

Цель документа — обеспечить единый и воспроизводимый процесс развертывания проекта в тестовой и продуктивной среде.

---

# 2. Целевая инфраструктура

Для работы проекта используются следующие компоненты:

* Ubuntu Server;
* Docker;
* Docker Compose;
* Nginx;
* PostgreSQL;
* Backend API;
* Telegram Bot;
* amnezia-api;
* AmneziaWG2.

---

# 3. Общая схема развертывания

```text id="n9t2fx"
                    Интернет
                        │
                        ▼
                    Nginx (HTTPS)
                        │
            ┌───────────┴───────────┐
            │                       │
            ▼                       ▼
       Backend API           amnezia-api
            │
            ▼
       PostgreSQL

Telegram Bot ───────────────► Backend API

amnezia-api ────────────────► AmneziaWG2
```

---

# 4. Состав Docker Compose

В рамках MVP все сервисы разворачиваются с помощью одного файла `docker-compose.yml`.

Планируемые контейнеры:

| Контейнер   | Назначение               |
| ----------- | ------------------------ |
| backend     | Backend API              |
| bot         | Telegram-бот             |
| postgres    | База данных PostgreSQL   |
| amnezia-api | Управление VPN-клиентами |
| nginx       | Обратный прокси и HTTPS  |

> **Примечание:** AmneziaWG2 устанавливается и обслуживается отдельно на VPN-сервере. Контейнеризация самого VPN-сервера в рамках MVP не предусматривается.

---

# 5. Назначение сервисов

## Backend API

Отвечает за:

* бизнес-логику;
* работу с PostgreSQL;
* взаимодействие с Telegram-ботом;
* взаимодействие с amnezia-api.

---

## Telegram Bot

Обрабатывает запросы пользователей и обращается только к Backend API.

---

## PostgreSQL

Хранит:

* пользователей;
* подписки;
* тарифы;
* устройства;
* историю платежей;
* журналы событий.

---

## amnezia-api

Предоставляет Backend API возможность:

* создавать VPN-клиентов;
* удалять клиентов;
* получать конфигурации;
* управлять VPN-инфраструктурой.

---

## Nginx

Используется для:

* HTTPS;
* обратного проксирования;
* ограничения доступа;
* обработки входящих запросов.

---

# 6. Переменные окружения

Все конфиденциальные данные должны храниться в файле `.env`.

Примеры:

```text id="4t9n8z"
BOT_TOKEN=
DATABASE_URL=
JWT_SECRET=

AMNEZIA_API_URL=
AMNEZIA_API_KEY=

POSTGRES_USER=
POSTGRES_PASSWORD=
POSTGRES_DB=
```

Файл `.env.example` должен содержать полный перечень переменных без реальных значений.

# 9. Обновление проекта

Рекомендуемый порядок обновления:

1. Создать резервную копию базы данных.
2. Получить новую версию проекта.
3. Пересобрать контейнеры.
4. Выполнить миграции базы данных.
5. Проверить состояние сервисов.
6. Проверить работу Telegram-бота.
7. Проверить создание VPN-клиентов.

---

# 10. Резервное копирование

Регулярному резервному копированию подлежат:

* база данных PostgreSQL;
* файлы конфигурации;
* Docker Compose;
* файл `.env`;
* журналы системы (при необходимости).

Рекомендуется автоматизировать создание резервных копий по расписанию.

---

# 11. Мониторинг

После развертывания необходимо контролировать:

* доступность Backend API;
* состояние PostgreSQL;
* доступность Telegram-бота;
* доступность amnezia-api;
* состояние VPN-сервера;
* загрузку процессора;
* использование оперативной памяти;
* свободное место на диске.

---

# 12. Безопасность

При эксплуатации системы необходимо соблюдать следующие требования:

* использовать HTTPS для всех внешних соединений;
* ограничить доступ к административным интерфейсам;
* регулярно обновлять программное обеспечение;
* использовать сложные пароли и секреты;
* хранить все секреты только в переменных окружения;
* вести журнал критических событий.

---

# 13. Масштабирование

Архитектура должна поддерживать:

* подключение нескольких VPN-серверов;
* размещение Backend API и PostgreSQL на отдельных серверах;
* использование внешнего балансировщика нагрузки;
* замену `amnezia-api` на собственный сервис управления VPN без изменения остальных компонентов системы.

---

# 14. План развития инфраструктуры

### Этап 1 (MVP)

* один сервер с Backend API;
* один экземпляр PostgreSQL;
* один Telegram-бот;
* один экземпляр `amnezia-api`;
* один VPN-сервер с AmneziaWG2.

### Этап 2

* несколько VPN-серверов;
* автоматический выбор сервера;
* централизованный мониторинг.

### Этап 3

* переход на собственный сервис управления VPN;
* горизонтальное масштабирование Backend API;
* отказоустойчивая инфраструктура.

---

# 15. Итог

На этапе MVP HighSpeedVPN разворачивается как единая система на базе Docker Compose с использованием Backend API, Telegram-бота, PostgreSQL, `amnezia-api` и Nginx. Такая архитектура обеспечивает быстрый запуск проекта, простоту сопровождения и возможность постепенного перехода к более масштабируемой инфраструктуре без изменения ключевых компонентов системы.
