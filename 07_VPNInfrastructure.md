# HighSpeedVPN — VPN Infrastructure

**Версия документа:** 1.0
**Дата создания:** 05.08.2026
**Статус:** В разработке

---

# 1. Назначение документа

Документ описывает архитектуру VPN-инфраструктуры проекта HighSpeedVPN, принципы взаимодействия компонентов, процесс выдачи VPN-доступа и подход к дальнейшему масштабированию.

На этапе MVP управление VPN осуществляется через **amnezia-api**, который взаимодействует с сервером **AmneziaWG2**.

---

# 2. Общая схема

```text
                Пользователь
                      │
                      ▼
               Telegram Bot
                      │
                      ▼
                Backend API
                      │
                      ▼
                 VPNService
                      │
                      ▼
                amnezia-api
                      │
                      ▼
               AmneziaWG2 Server
```

Все операции с VPN выполняются только через `VPNService`. Telegram-бот и остальные компоненты системы не обращаются к `amnezia-api` напрямую.

---

# 3. Компоненты инфраструктуры

## Telegram Bot

Отвечает за взаимодействие с пользователем:

* оформление подписки;
* запрос конфигурации;
* управление устройствами;
* отображение статуса подключения.

---

## Backend API

Выполняет бизнес-логику:

* проверяет подписку;
* выбирает VPN-сервер;
* обращается к VPNService;
* сохраняет информацию в базе данных.

---

## VPNService

Является промежуточным слоем между Backend и VPN-инфраструктурой.

Функции:

* создание VPN-клиента;
* удаление VPN-клиента;
* продление доступа;
* получение конфигурации;
* получение статистики;
* выбор VPN-сервера.

---

## amnezia-api

Используется как сервис управления VPN.

Через него выполняются:

* создание клиента;
* удаление клиента;
* получение конфигурации;
* управление сервером.

---

## AmneziaWG2 Server

Непосредственно обеспечивает VPN-подключение пользователей.

---

---

# 5. Жизненный цикл VPN-клиента

## Создание

При успешной оплате:

* создается запись в базе данных;
* создается VPN-клиент;
* генерируется конфигурация;
* конфигурация передается пользователю.

---

## Продление

При продлении подписки:

* обновляется срок действия;
* проверяется существование VPN-клиента;
* при необходимости конфигурация пересоздается.

---

## Отключение

После окончания подписки:

* клиент блокируется или удаляется;
* статус подписки изменяется;
* пользователь получает уведомление.

---

# 6. Управление устройствами

Каждое устройство рассматривается как отдельный VPN-клиент.

Для каждого устройства:

* создается собственная конфигурация;
* создаются уникальные ключи;
* назначается отдельный VPN-адрес.

Пользователь может:

* добавить устройство;
* удалить устройство;
* переименовать устройство;
* повторно скачать конфигурацию.

---

# 7. Работа с VPN-конфигурациями

Конфигурация содержит:

* параметры подключения;
* криптографические ключи;
* адрес сервера;
* назначенный VPN-адрес.

Конфигурация создается автоматически после создания клиента и сохраняется до момента удаления клиента или пересоздания конфигурации.

---

# 8. Выбор VPN-сервера

На этапе MVP используется один VPN-сервер.

В дальнейшем система должна поддерживать несколько серверов.

При наличии нескольких серверов Backend сможет выбирать сервер по различным критериям:

* стране;
* тарифу;
* текущей загрузке;
* доступности.

---

# 9. Мониторинг серверов

Backend должен регулярно получать информацию о состоянии VPN-серверов.

Контролируются следующие параметры:

* доступность сервера;
* количество активных клиентов;
* количество подключенных устройств;
* использование ресурсов;
* состояние службы AmneziaWG2.

При обнаружении недоступности сервера событие фиксируется в журнале и отображается администратору.

---

# 10. Безопасность

При работе с VPN необходимо соблюдать следующие требования:

* все соединения с `amnezia-api` должны быть защищены;
* доступ к API должен быть ограничен;
* конфиденциальные параметры не должны храниться в открытом виде;
* доступ к управлению VPN разрешен только Backend API;
* все действия должны журналироваться.

---

# 11. Масштабирование

Архитектура должна позволять:

* подключать новые VPN-серверы;
* распределять пользователей между серверами;
* выполнять обслуживание отдельных серверов без остановки всей системы;
* заменить `amnezia-api` на собственный сервис управления VPN без изменения Telegram-бота и бизнес-логики Backend.

---

# 12. Перспективы развития

В следующих версиях проекта планируется:

* поддержка нескольких VPN-серверов;
* автоматический выбор оптимального сервера;
* автоматическое распределение нагрузки;
* мониторинг качества соединения;
* резервирование серверов;
* собственный сервис управления VPN вместо `amnezia-api`.

---

# 13. Итог

VPN-инфраструктура HighSpeedVPN строится вокруг протокола **AmneziaWG2** и готового сервиса **amnezia-api**, который используется для управления VPN на этапе MVP. Все взаимодействие с VPN сосредоточено в `VPNService`, что позволяет сохранить модульность архитектуры и обеспечить возможность дальнейшего перехода на собственное решение без изменения остальных компонентов системы.
